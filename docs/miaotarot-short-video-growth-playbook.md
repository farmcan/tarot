# MiaoTarot 短视频增长与热点采集方法

**状态：** 已采用

**最后验证：** 2026-07-26
**适用范围：** MiaoTarot 获客短视频、怪问题栏目、热点候选采集、发布复盘

## 1. 核心判断

MiaoTarot 的传播单元不是“猫咪 + 塔罗”，也不是一条毒鸡汤，而是：

```text
怪问题（第一笑点）
→ 真实产品证明
→ 标准牌义
→ 发疯回答（第二笑点）
→ 评论区续题 / 打开产品
```

第一问先让人停，产品镜头证明这不是普通段子号，牌义负责恢复可信度，发疯回答负责截图和转述，评论负责生产下一集。

采用的产品假设：

- 用户第一次刷到时，先想知道“塔罗怎么接这道烂摊子”，而不是先学习产品。
- 用户愿意体验的前提，是看懂 MiaoTarot 真的有牌库、牌阵、亲手抽牌、标准牌义和后续动作。
- 发疯模式只能改变表达强度，不能改变抽牌结果、正逆位或标准牌义。
- “心理学型 / 科学型”是解释镜头，不是假装诊断或用科学证明塔罗。

## 2. 两种成片，各司其职

### 传播剪辑

建议 15–20 秒：

1. 0–3 秒：完整怪问题，不放 Logo 动画。
2. 3–6 秒：问题框 + 发疯模式 + 点击。
3. 6–9 秒：翻牌与标准关键词。
4. 9–14 秒：第二笑点。
5. 14–18 秒：评论区续题。

目标是停留、完播、重播、评论和主页访问。

### 产品解释版

建议 35–45 秒。当前母版为 39 秒，必须依次证明：

1. 正常 / 发疯两种表达。
2. 经典 22 张大阿卡纳与涂鸦 78 张全牌。
3. 单牌、双牌、三牌、四牌、选择权衡、关系剖面共 6 种牌阵。
4. 1–5 张与正逆位。
5. 用户亲手洗牌、切牌、抽牌；AI 不洗牌、不选牌、不换牌。
6. 牌名、牌位和标准含义先出现，猫语后出现。
7. 继续追问、最近 8 次、生成分享图。
8. 不预测命运，把最终选择留给用户。

传播剪辑负责“想看”，产品解释版负责“看懂和想试”。不要把全部功能重新塞回 18 秒版本。

## 3. 怪问题评分

每项 0–2 分，总分至少 8 分，且不能有 0：

| 维度 | 2 分标准 |
| --- | --- |
| 怪 | 脱离上下文也会产生“这也能问？” |
| 认 | 对应近期共同语境或人人遇过的生活摩擦 |
| 画 | 半秒能画成一个明确冲突 |
| 接 | 至少一张牌能准确接住，而不是硬贴段子 |
| 传 | 观众能复述、艾特朋友或自然补充下一题 |

再加三条硬门槛：

- 第一问本身必须是奖励，不能等答案才有趣。
- 答案必须提供新信息或新转折，不能只是换一种方式复述问题。
- 不拿死亡、灾害、疾病、自伤、未成年人伤害、贫困、身份和外貌做笑点。

可复用公式：

```text
人人见过的物件 / 行为
+ 把它拟人化成有明确动机
+ 把小麻烦升级成荒诞阴谋
+ 留一个准确牌义能接住的语义口
```

例：

- `袜子进洗衣机以后只回来一只，另一只是去留学了吗？`
- `冰箱半夜突然叹气，它是在制冷还是对我失望？`
- `路由器说会顺着网线找到我，它是想复合还是想重启？`
- `床单套被套时为什么总把我吞进去，它缺人还是缺德？`
- `连续 21 天不找充电线，它会主动现身吗？`

## 4. 热点不是题库，是模板来源

不要把热榜标题直接改成塔罗标题。采集后只提取：

- 句式模板；
- 情绪结构；
- 视觉动作；
- 参与方式；
- 生命周期阶段；
- 可合法复用的公共语境。

例如：

| 热点实例 | 可提取模板 | Miao 转译方向 |
| --- | --- | --- |
| `复盘一周穿搭思路` | 一本正经复盘日常 | `复盘一周被家中阴物件背刺` |
| `POV：当你突然……` | 第一视角角色错位 | `POV：当你半夜踩到猫砂` |
| `连续 21 天……会怎样` | 可验证挑战 / 日记 | `连续 21 天不找充电线` |
| `我会顺着网线找到你` | 物件威胁 / 追踪 | 路由器、打印机、蓝牙耳机拟人 |
| `下一个是谁` | 连载悬念 | 评论区决定下一件待审物件 |
| `上课时的难绷瞬间` | 群体经历合集 | `抽牌时最难绷的三种问题` |

只借模板，不搬运热门原图、原视频、完整台词或未获授权音乐。

## 5. 2026-07-26 热榜采集快照

本次用 `dailyhot-api@2.0.8` 在临时 Node 22 环境真实安装并启动本地服务。采集时间约为 `2026-07-26T10:08Z`：

- 抖音：50 条，返回 200。
- Bilibili：100 条，返回 200。
- 知乎：30 条，返回 200。
- 微博：当次返回 500。
- 项目公开示例域名从本机访问出现 TLS 连接失败；本地自托管抓取可用。

适合提取格式的当日样本：

- 抖音：`复盘一周穿搭思路`、`I'm so excited 舞蹈挑战`、`你最近过得还好吗`。
- Bilibili：`下一个是谁`、`POV：当你突然……`、`我会顺着网线找到你`、`连续21天十点睡六点起，我真的会变健康吗？`、`上课时的难绷瞬间`。
- 知乎：`香肠这东西到底是中国人自己发明的还是欧洲传过来的？`

处理决定：

- `复盘 / POV / 连续 N 天 / 下一个是谁 / 顺着网线`：保留结构，重新写 Miao 原创实例。
- 音乐挑战：只有能取得平台商业音乐授权、且猫塔罗能提供独有转译时才使用。
- `你最近过得还好吗`：更适合正常模式情绪内容，不硬塞进发疯栏目。
- 台风、死亡、医疗、未成年人伤害、政治和法律争议：即使热度高，也不进入喜剧候选。

热榜是观察日快照，不是长期事实。每条候选必须保存 `source`、`collectedAt`、`rank`、`hot`、`url` 和预计 TTL。

| [DailyHotApi](https://github.com/imsyy/DailyHotApi) | 3,970 / MIT | 多平台 JSON / RSS，npm 包可启动本地 API | 已真实安装、启动并取回抖音 / B 站 / 知乎；微博当次失败；**最快 pilot / 备用源** |

推荐组合：

```text
DailyHotApi：快速验证题材与字段
        ↓
TrendRadar：定时采集、去重、排名轨迹、关键词 / AI 筛选
        ↓
MCP / JSON 适配层
        ↓
Miao 模板提取、牌义匹配和安全评分
```

不要把采集依赖放进网站主包。它应是独立的内容运营任务；采集失败不能影响用户抽牌。

### DailyHotApi pilot

```sh
npm install dailyhot-api@2.0.8
```

```js
import serveHotApi from "dailyhot-api";

serveHotApi(3100);
```

然后从独立采集进程调用：

```js
const response = await fetch("http://127.0.0.1:3100/douyin");
if (!response.ok) throw new Error(`douyin source failed: ${response.status}`);
const payload = await response.json();
```

必须给每个源单独做超时、健康状态、退避和最后成功时间，不能因为一个平台 500 让整批失败。

### TrendRadar 主方案

采用前提：

- 用 Docker / 本地部署保存自己的 SQLite 数据。
- 将 `api_url` 指向自托管 NewsNow，避免把稳定性押在公共演示接口上。
- 通过 MCP 的 `search_news`、`aggregate_news`、平台对比和排名轨迹能力供 agent 使用。
- 只向运营侧暴露，网站运行时不连接。
- GPL-3.0 组件保持为独立服务；若分发修改版，按许可证履行义务。

## 7. 找到的 trend skills 为什么没有安装

官方 `openai/skills` curated 列表中没有热点采集 skill；请求实验目录时，该目录不存在。

第三方候选：

| Skill | 证据 | 决定 |
| --- | --- | --- |
| [scrollmark/social-skills: trend-radar](https://github.com/scrollmark/social-skills/blob/master/skills/trend-radar/SKILL.md) | MIT、生命周期和“模板 / 实例”区分很实用；仓库 13 Star | 只吸收方法。Skill 自身没有采集器，且引用仓库根目录共享 `references/`；只安装子目录会缺文件，**不安装** |
| [bytesagain/ai-skills: trend](https://github.com/bytesagain/ai-skills/blob/main/trend/SKILL.md) | 仓库 11 Star；命令只把用户输入写入本地日志 | 没有趋势数据、排名或检索，名称与能力不符，**拒绝** |
| [squire: trend-spotter](https://github.com/eddiebelaval/squire/blob/main/skills/trend-spotter/SKILL.md) | MIT、框架完整；仓库 18 Star | 是通用研究清单，没有可执行数据入口，**不安装** |

结论：目前更好的“skill”形态是 `TrendRadar / NewsNow MCP + 本文方法`。数据能力先可靠，提示词工作流才有意义。不要为了显示装了 skill，而安装一个只会复述“请多源验证”的空壳。

## 8. 为什么实时热点不做传统 RAG

实时热点的关键是时间、排名变化和跨平台扩散。传统向量 RAG 会弱化这些信号，还容易检索出已过期实例。

先存结构化时间序列：

```ts
type TrendSnapshot = {
  source: string;
  collectedAt: string;
  rank: number;
  title: string;
  hot?: number;
  url: string;
  normalizedTopic: string;
  template?: string;
  safety: "safe" | "review" | "reject";
  expiresAt: string;
};
```

只有以下内容适合进长期检索：

- 已验证的句式模板；
- 人工批准的怪问题—牌—回答；
- 发布后的停留、完播、分享和评论表现；
- 已确认的安全边界和失败案例。

历史样本达到约 500–1000 条、需要按主题和笑点机制找相似案例时，再给批准样本加 embedding。实时榜单本身继续按时间和排名查询。

## 9. 每日工作流

建议每 30 分钟采一次，发布前人工确认：

1. 拉取抖音、B 站、知乎、微博及垂直 RSS 的 Top 30–50。
2. 按 URL、规范标题和语义主题去重。
3. 计算排名速度、跨平台数和持续时间。
4. 先跑安全过滤；高风险新闻直接退出喜剧池。
5. 对剩余条目提取模板，不复制实例。
6. 每个模板生成 3 个 Miao 原创怪问题。
7. 给每题匹配 1–3 张可能接住的牌，并写出牌义依据。
8. 按“怪、认、画、接、传”评分。
9. 人工选题并检查画面权利、音乐权利和品牌独特性。
10. 发布后回写停留、3 秒留存、完播、重播、分享、有效续题和开始抽牌率。

热点分数建议：

```text
25% 跨平台扩散
+ 20% 排名速度
+ 20% 模板可提取性
+ 20% Miao 牌义适配
+ 15% 安全与素材可控性
```

任何安全门槛失败都直接淘汰，不用总分补偿。

## 10. 分镜与制作规则

- 第 0 帧显示完整怪问题，不先解释品牌。
- 1–3 秒必须出现视觉变化，但不能靠乱闪掩盖信息。
- 产品证明使用真实能力和真实卡牌，不写尚未上线的功能。
- 当前解读牌是移动端主视觉，给独立全宽区域；不和长段解释挤在窄分栏。
- 旁白和主文案表达同一件事；静音仍能看懂。
- 音轨必须验证 AAC 编码、响度、全片解码和真实浏览器波形。
- 平台播放器可能默认静音；成片前段保留 `🔊 有声口播` 提示，但不能拿提示代替实际音轨验证。

当前确定性制作链路：

```text
热榜采集
→ 模板提取与问题评分
→ 牌义匹配
→ ImageGen 原创首帧
→ Remotion 分镜与字幕
→ 关键帧手机复审
→ H.264 + AAC 渲染
→ ffprobe / ffmpeg / 浏览器音频波形验证
→ 发布与指标回流
```

## 11. 当前交付

- 传播短版：`marketing/miaotarot-social-launch/remotion/out/miaotarot-hot-meme-ginger-final-v2-18s-1080x1920.mp4`
- 产品解释版：`marketing/miaotarot-social-launch/remotion/out/miaotarot-product-tour-final-39s-1080x1920.mp4`
- 关键帧：`marketing/miaotarot-social-launch/snapshots/product-tour/`
- 可复现源码：`marketing/miaotarot-social-launch/remotion/src/MiaoTarotProductTour.tsx`

39 秒母版的最终验证：

- Mediabunny：39.0187 秒、1080×1920、AVC + AAC、48kHz 双声道。
- `ffmpeg ebur128`：整体约 −15.5 LUFS，真峰值约 −3.3 dBFS。
- 以 −45dB、0.5 秒阈值检测：没有超过 0.5 秒的无声段。
- 完整解码通过。
- Chromium 实播：视频持续前进，音频上下文运行，时域波形峰值偏离静音中心 78。

发布不是“保证爆”。用数据拆问题：

- 1 秒停留 / 选择观看差：先换问题。
- 3 秒留存差：产品露出太慢或首帧承诺不清。
- 完播差：中段证明太多、没有持续变化。
- 重播 / 分享差：第二笑点不够可复述。
- 评论多但开始抽牌少：段子成立，产品证明失败。
- 开始抽牌高但完成低：回到真实产品体验处理，不继续改广告。
